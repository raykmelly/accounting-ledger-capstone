# Accounting Ledger

A command-line Java application for tracking financial transactions, for a business or for personal use. Every deposit and payment is saved to a plain-text file, and the ledger can be viewed in full, filtered, run through pre-defined reports, or searched with a custom multi-field filter. The app is branded as **Melly Bank** and has a styled terminal interface with a launch screen, bordered menus and aligned transaction tables.

Built as Capstone 1 for the Pluralsight Java development program.

## Features

- **Record deposits and payments** with a description, vendor and amount. Each entry is stamped with the current date and time and saved automatically.
- **Ledger view** showing all entries, deposits only, or payments only, always sorted newest first.
- **Reports** for the current month, previous month, current year, previous year, or all transactions from a single vendor.
- **Custom search** that filters by any combination of start date, end date, description, vendor and amount. Any field can be skipped by pressing Enter.
- **Styled terminal interface.** A launch screen, bordered menus, and transaction tables with deposits shown in green and payments in red.
- **Input validation.** Invalid numbers and dates are rejected with a message and the prompt repeats, so a typo does not end the program.
- **Persistent storage.** Transactions are read from and saved to `transactions.csv`, so data carries over between sessions.

## Requirements

- Java 17 or later
- A terminal that supports ANSI colors and UTF-8, such as the IntelliJ IDEA console, Windows Terminal or the macOS Terminal
- Maven (optional, only needed to build from the command line; an IDE such as IntelliJ IDEA can run the project directly)

## How to Run

1. Clone the repository:

   ```bash
   git clone https://github.com/raykmelly/accounting-ledger-capstone.git
   cd accounting-ledger-capstone
   ```

2. Compile the source:

   ```bash
   javac -d out src/main/java/com/pluralsight/*.java
   ```

3. Run the application from the project root, so it can find `transactions.csv`:

   ```bash
   java -cp out com.pluralsight.AccountingLedgerApp
   ```

If you use IntelliJ IDEA, open the project folder and run `AccountingLedgerApp`. Make sure the working directory is the project root.

## Usage

The app opens on a launch screen. Press Enter to continue to the home screen.

### Home screen

| Option | Action |
| ------ | ------ |
| `D` | Add a deposit |
| `P` | Make a payment (debit) |
| `L` | Open the ledger |
| `X` | Exit the application |

### Ledger screen

| Option | Action |
| ------ | ------ |
| `A` | Display all entries |
| `D` | Display deposits only |
| `P` | Display payments only |
| `R` | Open the reports screen |
| `H` | Return to the home screen |

### Reports screen

| Option | Action |
| ------ | ------ |
| `1` | Month to date |
| `2` | Previous month |
| `3` | Year to date |
| `4` | Previous year |
| `5` | Search by vendor name |
| `6` | Custom search |
| `0` | Back to the ledger |

Menu letters are not case sensitive. Deposit amounts must be positive and payment amounts must be negative.

### Custom search

Option `6` on the reports screen prompts for each of the following. Press Enter on any prompt to skip that filter, and only the filters you fill in are applied.

| Field | How it matches |
| ----- | -------------- |
| Start date | Transactions on or after this date (`YYYY-MM-DD`) |
| End date | Transactions on or before this date (`YYYY-MM-DD`) |
| Description | Case-insensitive, matches any part of the description |
| Vendor | Case-insensitive, must match the full vendor name |
| Amount | Exact amount. Payments are stored as negative numbers, so search for `-35.39`, not `35.39` |

After the results are shown, the app asks whether you want to search again or return to the reports screen.

## Data Format

Transactions are stored in `transactions.csv`, one per line, with fields separated by a pipe (`|`):

```
date|time|description|vendor|amount
```

```
2026-11-02|12:49:50|Invoice 0001 paid|Joe|1500.0
2026-11-03|09:12:32|Gas|Valero|-35.39
```

Positive amounts are deposits and negative amounts are payments. The file has no header row. If you edit the file by hand, keep the last line followed by a newline so new entries are not appended to it.

### Design notes

- On startup, `loadTransactions()` reads the CSV once into an `ArrayList<Transaction>` and sorts it newest first with a `Comparator` on date and then time.
- The ledger, every report and the custom search work on that in-memory list rather than re-reading the file.
- Each report collects its matching transactions into a list and hands the list to `UserInterface.transactions(...)`, which prints the table, the row count, or a "No transactions found" message.
- The custom search treats each filter as optional. A transaction is skipped with `continue` as soon as it fails a filter that the user filled in, and any transaction that survives every check is kept. Unused filters are `null` or empty, so they never exclude anything.
- User input is always read with `nextLine()` and converted with `Integer.parseInt`, `Double.parseDouble` or `LocalDate.parse` inside a `try/catch`, which avoids the common `Scanner` newline problem and handles bad input without crashing.
- New transactions are appended to the file and inserted at the front of the list, so the list stays newest first.
- `Transaction` converts to and from a CSV line with `toCsvLine()` and `fromCsvLine()`, which keeps the file format in one place.
- All look-and-feel code lives in `UserInterface`, so the ledger logic contains no color codes or border characters.
